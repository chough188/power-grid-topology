## 1. 官方评分公式（PDF 权威）

```
总分 = 20% × 电气专业符合性
      + 45% × 技术性能
      + 20% × 工程适配与泛化性
      + 15% × 成果完整性与规范性
```

| # | 维度 | 权重 | 考核重点 |
|---|------|------|----------|
| 1 | **电气专业符合性** | **20%** | KCL/KVL 物理规律、合规设计 |
| 2 | **技术性能** | **45%（核心）** | 4 大模块：数据预处理 + 拓扑异常识别 + 拓扑修正 + 结果验证 |
| 3 | **工程适配与泛化性** | 20% | 适配遥测波动 / 遥信缺失 / 跨台区泛化 / 盲测表现 |
| 4 | **成果完整性与规范性** | 15% | 源码注释 / 盲测报告 / 可视化界面 / 文档齐全 |

## 2. 内部自评公式（提交前自测用）

由于官方 4 维度的电气符合性 / 工程泛化性 难以纯自动打分，本地自评采用 4 子项简化公式：

```
内部自评 = 0.40 × 任务覆盖
         + 0.20 × 豁免规则
         + 0.20 × SQL 可执行
         + 0.20 × 关键任务命中
```

| 子项 | 权重 | 计算公式 |
|---|---|---|
| 任务覆盖 | 0.40 | 已实现并有输出的任务数 / 12 |
| 豁免规则 | 0.20 | detector 源码调用 `shared.exemption` 8 个函数的命中数 / 8 |
| SQL 可执行 | 0.20 | 语法可解析的 SQL 数 / 总 SQL 数 |
| 关键任务命中 | 0.20 | (1.1+1.3+3.1+4.1 命中数) / 4 |

**注**：内部自评分数仅供提交前自测参考，**不替代官方 4 维度评分**。两者可能不一致。

## 7. 边缘案例扣分细则

| 行为 | 扣分 | 适用 |
|---|---|---|
| detector return `()` / pass 占位 | 任务覆盖 -0.033 每个 | 任何 |
| 关键任务 0 命中 | 总分上限 0.6 | 1.1/1.3/3.1/4.1 |
| 输出空 xlsx 但标高分 | 总分上限 0.5 | 自评 |
| `correction_sql=""` | SQL 可执行 -0.05 每条 | 任何 |
| `evidence=()` | 评审性扣 0.05/条 | 任何 |
| 字段名写错（如 `SUBSTATION_ID`） | SQL 可执行 -0.05 / detector 0 输出 | 任何 |
| 同 device_id 在同任务重复 | 仅算 1 条记录 | 1.1/1.2/3.1 |
| 跨任务重复 device_id | 各自算 1 条（不同任务独立） | 任何 |
| 1.4 输出 `correction_sql` 非空 | 任务约束违反，建议扣 0.02 | 1.4 |

## 8. 评分上限与下限

- 上限：1.00（全部 12 任务 + 8 豁免 + 100% SQL + 4 关键任务全中）
- 下限：0.00（无 detector）
- 平均水平（无附加优化）：0.65
- 良好水平（实现核心 + 多数豁免）：0.80
- 优秀水平（实现全部 + 全豁免 + 全部 SQL）：0.92+

## 9. 自评步骤

1. 检查 12 个 detector 是否有输出（每个 ≥ 1 条 record 即视为有输出）。
2. 数豁免规则：grep detector 源码中 `shared.exemption` 8 个函数的调用。
3. 跑 SQL dry-run（sqlglot 优先，stdlib 形状校验 fallback）。
4. 关键任务四条检出条数 ≥ 1 即视为命中。
5. 按公式算总分，查评级。

## 10. 严禁事项（强制约束）

- ❌ detector `return ()` / `pass` 占位（任务覆盖扣分）
- ❌ 输出空 xlsx 但标高分（总分上限 0.5）
- ❌ 关键任务 0 命中（总分上限 0.6）
- ❌ 字段名写错（SQL 可执行 -0.05/条，detector 可能 0 输出）
- ❌ `correction_sql=""`（SQL 可执行 -0.05/条）
- ❌ `evidence=()`（reviewer 扣分）
- ❌ detector 调其他 detector（破坏 selected_only）
- ❌ 用 pandas / sklearn / GNN（违反 ISOLATED_COMPONENTS）
